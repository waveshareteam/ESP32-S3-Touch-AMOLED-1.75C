# Contributing

Thank you for helping improve this repository.

## Pull Requests

1. Open an issue first when the change is large or changes public behavior.
2. Keep changes focused on one example, workflow, or documentation area.
3. Use repo-relative paths in descriptions and validation notes.
4. Do not include local machine paths, usernames, virtual environments, or host-specific setup details in public text.
5. Let GitHub Actions validate build changes.

## Examples

When changing an example, include the framework version, board target, and CI result in the pull request.

Do not add generated build outputs, downloaded artifacts, or local dependency caches to source control.
